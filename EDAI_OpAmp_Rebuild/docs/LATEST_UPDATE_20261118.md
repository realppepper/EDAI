# 2026-11-18 공유 갱신

## 이번에 추가한 내용

이전 공유 이후 작업한 단계별 검증 공통 구조와 실행 조건 대조, 재시도/캐시 점검, 잡음 입력 저항과 추가 측정 보완, Optuna 선택 기능을 반영했습니다. 실행 원자료와 개인 환경은 제외하고 실행 코드·테스트·설명 문서를 공유합니다.

- `validation_01`~`validation_05`: 검사 결과 형식, 독립 SPICE 읽기, 계획/실행/측정 조건 대조, 재시도·캐시 및 별도 경로 확인.
- `verify_09`~`verify_11`: 스칼라 입력 저항, 추가 검사항목, 정착시간 측정 지원. 해당 함수가 있다고 모든 제품 사양을 검증할 수 있다는 의미는 아닙니다.
- `optuna_01`~`optuna_06`와 `run_optuna_sizing.py`: 변수/범위 검증, 기존 선별 어댑터 재사용, 기동 보완 제안, 전체 검사 기반 후보 선택과 재개.
- 기존 루프/워크플로 진입점에 Optuna 선택 설정 전달. 기본값은 꺼짐이며 설계 API는 아직 미연결.

## 이번 확인의 범위와 결과

로컬 원본의 자동 검사418개가 통과했습니다. 최신 Optuna 연결 확인은 LM358B의80조건 계획에서58개 통과,15개 모델 미검증,7개 어댑터 미검증과 별도 기동5개 전원점 통과였습니다.

최대3회/180초 탐색 예산에서2개 후보를 평가하고1개 후보를 전체 재검증했습니다. 시작 후보도 기동에 통과했으므로 이 시험을 Optuna가 기동 실패를 해결하거나 LLM보다 효율적임을 입증한 실험으로 해석하면 안 됩니다. 알려진 기동 실패는 별도의3V 실제 실행으로 재현해 제약 위반 처리 경로를 확인했습니다.

완료된 연구를 같은2회 예산으로 재개했을 때736개 데크/파형/로그의 크기·수정 시간을 유지했고 시행2개/전체 검증1개를 유지했습니다. 원자료와 코드 서명도 확인했습니다. 이 캐시는 Git에 포함하지 않습니다.

이전 A/B 최대5회 수정 실험에서는 A가5회,B가4회에 구현 범위를 통과했지만 **실제 Optuna 호출은0회**였습니다. AI 출력이 달라진 영향과 Optuna 효과를 구분할 수 없으므로 Optuna의 장점으로 보고하지 않습니다. 이후 호출 정책을 보완한 것이 이번 갱신입니다.

## 후보 선택 보완

- 완전하고 현재 회로에 연결된 기동 파형에서 미달이 확인되면 R/C 또는 W/L 탐색을 제안할 수 있습니다.
- 불완전 측정, 모델 미검증, 실행 오류는 물리적 사양 미달 점수로 만들지 않습니다.
- IQ/GBW/PM/SR 밖의 유효한 수치 미달 때문에 호출을 일괄 차단하지 않습니다. 해당 항목들의 미달 정도가 모두 Optuna의 선별 목적함수에 들어간 것은 아니며 최종 전체 검사에서 확인합니다.
- 전력이 사실상 같으면 선별 성능의 여유로 순위를 정합니다. 실제 사양 합격 기준은 바꾸지 않습니다.
- 첫 후보의 전체 검사 미달 시 기본 최대3개까지 순서대로 확인합니다. 모두 미달하면 성공으로 표시하지 않고 이력과 함께 설계자에게 돌아갑니다.

## 이어서 할 일

[README의 남은 과제](../README.md#현재-남은-과제)를 기준으로 다른 데이터시트에서 일반화, 미검증 성능의 모델/어댑터 범위, 하네스/하네스²/Optuna의 효과, 설계 API·토큰 기록, UI/블록 조합 통합을 진행합니다.

공통 검증 구조를 구현했다고 PDF 원문이나 모든 SPICE 표현의 정확성을 증명하는 것은 아닙니다. 과거 예시의 확대 계획74+29조건과 이번58+22조건은 검사 정책이 달라 통과율을 직접 비교하지 않습니다.
