# 시스템 흐름과 책임 경계

## 입력부터 검사 계획까지

| 순서 | 코드 계열 / 실행 진입점 | 입력 | 출력·확인 사항 |
|---|---|---|---|
| 1 | `pdf_01`, `pdf_02` / `run_pdf_overview.py` | PDF, 목표 제품 | 전체 페이지 텍스트·좌표·후보 페이지. 앞 몇 쪽으로 고정 제한하지 않음 |
| 2 | `pdf_03`, `pdf_04` / `run_pdf_layout.py` | 페이지 계획, API 키 | 이미지·Nemotron 응답·배치 블록·재사용 서명 |
| 3 | `pdf_05` | 원문/파싱 결과 | 빈 응답·잘림·표 구조와 내용 누락 후보 |
| 4 | `spec_01` → `spec_02` → `spec_03` / `run_spec_pipeline.py` | 코드 행 + LLM 의미 주석/검토 | 같은 행 ID의 사양 문서, 숫자·조건·각주·출처 검사 |
| 5 | `chart_01`, `chart_02` / `run_chart_references.py` | 사양·그래프·검토 파일 | 캡션/축/조건 메타데이터와 사양 연결. 수치 사용 승인과 구분 |
| 6 | `hkg_01`, `hkg_02`, `hkg_query` / `run_hkg.py` | 검토된 사양·참고 정보 | 사양·조건·출처·검토 상태 노드와 조회 문맥 |
| 7 | `pdg_01`~`pdg_05` / `run_pdg.py` | HKG·원문·핀/동작 주석 | 핀/채널/관계, 출처 감사, 명시적 실행 정책·시각화 |
| 8 | `plan_01`~`plan_04` / `run_measurement_plan.py` | HKG·PDG·프로젝트 정책 | 목표 선택·조건 해석·측정 방법·실행 계획과 검증 |

원문 값이 모두 합격 기준이 되는 것은 아닙니다. 정격·동작 범위·MIN/TYP/MAX·시험 조건을 보존한 다음 프로젝트 목표를 명시적으로 선택합니다. 원문의 TYP를 목표로 채택해도 제조사 보증값으로 바뀌는 것은 아닙니다.

## 설계·검증 루프

```text
run_fixed_harness_loop.py start
  → 최초 후보와 동결 계획/지침/코드 저장
  → run_verification_pipeline.py
      기본 검사 → 입력 임피던스 → 과부하 회복 → 80조건 대장
  → 구현된 목표 미달이면 REQUEST_001.json
  → 설계자(현재는 채팅 AI)가 응답 JSON 작성
  → submit: 응답과 전체 넷리스트 검증·저장
  → 같은 전체 EDA 검사
  → 최선 후보 보존 / 다음 요청 / 성공 또는 예산 종료
```

`harness_01_fixed`는 지침과 DUT 경계, `harness_02_request`는 입력/응답 계약, `harness_03_loop`는 상태와 종료·재개를 담당합니다. 회로의 물리적 실패 원인은 LLM의 가설이며, 최종 수치와 판정은 고정 검사 코드가 결정합니다.

측정 가능한 항목도 유효 동작점·분석 성립·완전한 데이터가 필요합니다. 수치가 작게 나왔다고 모델에 없는 누설/잡음까지 통과시키지 않습니다. 미검증 조건은 전체 대장에서 삭제하지 않습니다.

## 코드와 AI가 하는 일

| 작업 | 현재 담당 |
|---|---|
| 페이지 탐색·이미지 생성·행 ID/원문 셀 | Python / PyMuPDF |
| 이미지 문서 파싱 | Nemotron Parse API |
| 의미/조건 검토·그래프 검토·PDG 해석 | AI가 검토한 JSON 파일 전달 |
| 계획 구성·검사 실행·측정·상태/해시 검증 | Python / LTspice |
| 회로 수정 제안 | AI가 전체 넷리스트 JSON 전달 |
| 설계용 API 전송·자동 모델 전환 | 미연결 |
| 지침 자체 수정(Harness²) | 미적용 |

## 주요 식별자와 저장

- `row_id`: 원문 근거와 사양 행의 연결. 다른 원문/좌표에 무조건 재사용하지 않습니다.
- `case_id`: 사양에 필요한 전원·부하 등의 검사 사례. 한 사례에 복수 하위 측정이 있을 수 있습니다.
- `request_id`: 설계 응답이 어느 요청의 것인지 확인합니다.
- `STATE.json`: 완료·중단·pending과 동결 서명의 기준 기록입니다.
- `BEST.json`, `REPORT.md`: 기준 상태에서 재구성 가능한 조회 결과입니다.
- 원문·회로·계획·코드가 바뀐 과거 체크포인트는 그대로 재개하지 않습니다.

`manual_inputs`는 검토 내용의 사례이지 최신 PDF에서 자동으로 유효한 정답 파일이 아닙니다. `examples`와 `tests/fixtures`도 실행 준비가 끝난 run 폴더가 아닙니다.
