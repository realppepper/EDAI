# 성공 종료 시 스케마틱 자동 생성

현재 운영 경로는 구현된 검사 범위와 필수 기동 검사를 통과해 `implemented_scope_passed`로 종료할 때, 최종 채택 회로의 LTspice 스케마틱을 자동 생성한다. 고정 하네스 루프, 연속 하네스² 운영 루프, 데이터시트부터 시작하는 상위 경로에 연결했다.

결과 폴더:

```text
<세션>/schematic/FIRSTAMP.asc
<세션>/schematic/candidate_source.inc
<세션>/schematic/MANIFEST.json
```

`.asc`는 LTspice에서 열 수 있는 회로도이다. 원본 소자명·MOS 네 단자·W/L·저항·커패시터·모델을 보존한다. 같은 노드 이름은 전기적으로 연결되며, 소자를 격자로 배치한 라벨 연결 방식이다. 회로의 기능 블록을 추정하거나 내부 구조를 제조사 회로처럼 재배치하지 않는다. 전원·입력·부하·해석 명령은 별도 테스트벤치에 있고, 이 도면은 DUT만 담는다. 소자 수나 이름을 이전49 MOS 회로로 고정하지 않는다.

저장 전에는 도면의 심볼 단자 좌표·배선·라벨에서 연결을 다시 읽어 원본 넷리스트와 대조한다. 이 정적 대조는 매번 실행한다. 자동 종료 단계에서 LTspice를 다시 실행하지 않으며, manifest의 `native_netlist_verification`도 `not_run`으로 명시한다. 구현 확인에서는 실제 LTspice로49 MOS 회로를 넷리스트화해59소자/모델 일치를 별도로 확인했다. 도면만 만든 뒤 성능을 재검사했다고 주장하지 않는다.

`STATE.json`, 고정/운영 루프의 `REPORT.md`, 명령 실행 결과에 도면 위치와 상태를 표시한다. `deliverables_complete:true`는 도면과 원본 사본까지 생성됐다는 뜻이다. 전기적 성공 판정은 현재 구현 범위에 한정하며, 미검증 사양까지 통과했다거나 제작 가능한 IC가 완성됐다는 뜻은 아니다.

저장 실패 시 전기적 통과 결과를 보존하고 `schematic.status:export_failed`, `deliverables_complete:false`와 오류를 남긴다. 완료 상태에서 `resume`하면 도면 생성을 재시도하며 새 설계 제안이나 시뮬레이션을 소모하지 않는다. 이미 생성한 정상 파일은 다시 쓰지 않고, 사용자가 수정한 파일은 덮어쓰지 않는다. 예산 소진·실행 중단·성능 미달 종료는 성공 도면을 만들지 않는다.

기존 동결 세션은 이전 코드와 결과를 보존한다. 새 코드를 적용하기 위해 과거 실행의 코드 해시를 바꾸거나 과거 성공 결과를 재작성하지 않는다.
