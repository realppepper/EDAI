# 진행 요약

## 1. 방향과 재구성

조원의 AnalogVerifier 실행 흐름을 재검토한 뒤, 독립 폴더에서 필요한 부분을 단계별로 재구성했습니다. 현재 대상은 op amp입니다. 목표는 모델 자체를 새로 학습시키는 것이 아니라, 같은 LLM도 설계·검증·피드백 구조에 따라 결과가 달라지는지 확인하는 것입니다.

## 2. PDF와 사양 처리

PDF 전체 페이지의 텍스트·좌표를 가볍게 탐색하고 후보 페이지를 정합니다. 필요한 페이지를 이미지로 만들어 Nemotron Parse에 전달합니다. 구조 검사 후 코드는 공통 행 ID와 원문 셀을 만들고, LLM은 그 행에 의미 정보를 보완합니다. 서로 독립적인 두 사양 JSON을 합치는 흐름으로 만들지 않았습니다.

숫자·MIN/TYP/MAX·조건·각주·출처를 대조하고, 추가 의미 검토와 누락 점검을 구분했습니다. 특성곡선은 참고 정보로 연결하며 곡선 전체 수치를 검증한 것으로 표시하지 않습니다.

## 3. HKG·PDG·검사 계획

HKG는 사양·조건·출처·검토 상태를 연결합니다. PDG는 원문 핀/채널/동작 관계를 관리하고, 문서에 없는 지연은 임의 생성하지 않습니다. 목표 선택과 검사 계획에서는 원문 정보와 프로젝트에서 채택한 조건을 구분했습니다.

LM358B 기준 원문 42행 중 프로젝트 범위의 32행을 80개 사례로 구성했습니다. 온도 계수·온도 변형 행 등의 범위 결정은 정책과 함께 보존했습니다.

## 4. 회로와 EDA 검사

일반 MOS 모델로 회로를 구성하고 LTspice에서 DC, AC, 안정성, 시간 응답, 전원·부하·입출력 및 과부하 회복 검사를 확대했습니다. 알려진 답을 가진 기준 회로와 미달 기준도 사용해 판정 코드를 확인했습니다.

MOS 크기/전류/보상과 출력단 수정 등을 진행했습니다. 현재 공유한 18pF 회로는 58조건 통과, 모델·검사기 한계 22조건 미검증입니다. 실제 TI 칩 복제나 제조 가능한 PDK 설계 완성을 의미하지 않습니다.

## 5. 고정 하네스와 루프

조원 지침을 검토해 채택·수정·제외 근거를 남기고 `harness/fixed_v1.json`에 고정했습니다. 목표·측정 결과·실제 검사 계약을 설계자에게 전달하고, 수정 넷리스트를 전체 재검증한 뒤 최선 후보를 보존합니다. 설계 판단은 현재 채팅 AI의 JSON 응답이며 프로그램이 그 채팅을 자동 호출하지 않습니다.

## 6. 판정 보완

DC 스윕이 계산 지점을 누락해도 남은 점만으로 통과시키던 오류를 발견했습니다. 원래 격자 전체 검사, 중앙에서 양쪽으로 계산, 수치/누락 실패에만 원래 전체 스윕으로 재시도를 추가했습니다. 18pF를 새로 전체 검사해 결과를 확인했습니다. 예전 통과 수와 새 엄격한 재검증을 구분합니다.

## 7. 비교와 안정화

대화 이력이 없는 에이전트 두 개에 같은 초기 회로·피드백·수정 기회를 주고 한쪽에만 추가 지침을 제공했습니다. 최신 단회 비교는 둘 다 57통과, 36V 과부하 회복 미달 1개였습니다. 지침 효과를 입증하지 못했고 단일 과제로 일반화할 수도 없습니다.

비교 중 결과 저장 접근 거부가 발생해, 이후 원자적 저장 재시도와 같은 후보의 검증 재개를 보완했습니다. 실제 Windows 읽기 잠금, 오류 주입, 새 프로세스 재개, 최선 후보/보고서 일치와 중복 제출을 확인했습니다. 최종 코드 검사 192개 통과, 기존 18pF의 80조건 판정과 일치했습니다.
