# 단계별 검증의 공통 구조와 실행 조건 대조 — 1차 범위

> 아래 1차 범위는 최초 구현 기록이다. 이후 진행한 재시도·캐시·추가 경로 보완은 문서 마지막에 별도로 정리했다.

이번 변경은 백업, 공통 결과 형식, 계획→SPICE→측정 조건 대조까지다.
회로 최적화, 검증 LLM, API 연결, 재시도/캐시 구조 개편, 실제 LTspice 재실행은 하지 않았다.

## 파일과 역할

| 파일 | 역할 |
|---|---|
| `opamp_pipeline/validation_01_results.py` | 검사 대상·기대값·실제값·판정·근거·한계를 담는 공통 결과 형식과 저장 |
| `opamp_pipeline/validation_02_spice_reader.py` | 생성 코드와 독립적으로 실제 SPICE의 소자, 숫자 단위, PWL, 해석 명령을 읽기 |
| `opamp_pipeline/validation_03_execution_contract.py` | 입력 계획에서 기대 조건을 먼저 만들고 실제 데크와 측정 인자를 대조 |
| `run_validation_report.py` | 기존 단계별 JSON 결과를 원본 해시와 함께 공통 보고서에 연결 |
| `tools/audit_execution_contracts.py` | API/시뮬레이터 없이 계획으로 생성한 데크의 조건 일치 여부 확인 |

기존 검증 시점과 검사 내용은 유지한다. PDF 파싱 검사는 `pdf_05_check_layout.py`,
사양 원문 대조는 `spec_03_verify_sources.py`, HKG는 `hkg_02_validate.py`,
PDG는 `pdg_02_validate.py` 및 `pdg_03_audit.py`, 검사 계획은 `plan_04_validate.py`가 담당한다.
이 파일들을 하나의 거대한 검사 함수로 합치지 않았다. 기존 결과를 연결할 때는 원본 판정을 그대로
보존하고, 보고서에 연결됐다는 이유로 새롭게 검증됐거나 통과했다고 해석하지 않는다.

## 새 회로 검사 흐름

1. `build_fixture()`가 입력 item/case와 명시된 어댑터 정책에서 기대 조건을 먼저 구성한다.
2. 기존 생성 코드가 SPICE와 측정 인자를 만든다.
3. `run_extended_verification.py` 및 `verify_10_additional.py`의 실행 경계에서 독립 리더로 조건을 대조한다.
4. `verify_02_metrics.measure()` 진입 시 실제 실행된 파일과 지금 사용할 측정 인자를 다시 대조한다.
5. 대조가 통과한 뒤에 기존 파형 측정과 사양 판정을 수행한다.

조건이 다르면 `ExecutionContractError`로 차단하고, `physical_spec_failure_established=False`와
기대값/실제값을 기록한다. 정상 실행 시 `execution_contracts/`에 근거 JSON을 남긴다.
기존 완료 결과와 동결된 제어기 서명은 수정하지 않는다. 변경된 코드로 재개가 거부되는 과거 실행은
서명을 고쳐 강제 재개하지 않고 새 결과 폴더를 사용해야 한다.

## 이번 버전의 검사 범위

- 전원 레일·중간 전압·온도·DUT 단자 연결·모델 include 경로
- 저항/전류 부하 및 연결점, 부하 커패시터
- DC 스윕 범위/방향/간격과 AC/잡음/과도 해석 명령
- 과도 입력의 시작/끝 전압, 상승/하강 방향, 전이·관찰·최대 시간 간격, 단위 접미사
- 정착 오차 비율 및 입력 전이 종료 기준, 관찰 종료까지 밴드 내 잔류하는 측정 정의
- 슬루율 10–90% 정의, 출력 전류 방향/클램프, 대칭 출력 스윙 방향
- 출력 저항/잡음의 계획 측정 주파수와 실제 해석/측정 주파수
- 측정 함수 종류, 측정에 전달하는 fixture/step 인자의 일치 여부

원문 조건과 프로젝트 정의, 수치 해석 정책, 분석용 기준 회로의 상수를 구분한다.
예를 들어 DC 200구간, GBW 탐색 .01Hz–1GHz, 기본 과도 관찰 40µs/최대 간격 2ns는
이 어댑터가 명시한 수치 정책이다. 데이터시트에서 추출한 값이라고 표현하지 않는다.
기준 회로는 제품 전원 범위와 별개이므로 제품 전원으로 강제로 바꾸지 않는다.
헤더의 온도는 더 이상 고정 문자열 25가 아니라 fixture의 명시적 온도를 사용한다.
다른 조건을 지원하지 않는 어댑터는 조건을 조용히 무시하는 대신 불일치로 차단할 수 있다.

## 아직 포함하지 않은 것

- 원문 해석의 정답 보장, 원문 전체 누락 여부의 새로운 재검사
- DUT 내부 회로의 연결·물리적 타당성을 증명하는 전체 SPICE 검증
- 시작 파형 생성 보조 데크, 별도 입력 임피던스/과부하 확장 경로의 계약 연결
- 직접 작성한 일부 기준 회로 데크의 계약 연결: `not_checked`로 기록하며 통과로 간주하지 않음
- 자동 재시도/캐시의 계약 전파 및 결과 재사용 정책 보완
- 실제 LTspice를 이용한 새 종단 간 실행 검증

지원 문법 밖의 관련 표현은 통과로 추정하지 않는다. 현재 리더는 우리 fixture의 명시적 숫자와
제한된 PSRR 대칭 전원 식을 다루며, 범용 SPICE 해석기나 UVM 구현이 아니다.
계약에 없는 조건 전체가 검사됐다는 의미도 아니다. 결과의 한계를 함께 읽어야 한다.

## TL071C 오프라인 확인

원래 검사 계획과 추가 정착시간 요청으로 생성한 방향별 실행 22개 중,
21개는 이번 조건 대조를 통과했고 1개는 잡음 입력 저항 조건 불일치로 차단됐다.
원문 조건은 입력 소스 저항 20Ω인데 기존 잡음 fixture는 이상적 전압원으로 직접 구동한다.
새 검사는 이를 0Ω으로 확인해 오류를 기록한다. 해당 fixture를 변경하거나 원문 목표를 낮추지 않았다.

이 결과는 회로 성능 통과율이 아니다. 과거 TL071C의 추가 정착시간 성능 실패와
모델 미검증 판정도 그대로 보존한다. 단계별 기존 보고서와 새 계약 영수증은 별개다.

## 추가 보완: 재시도·캐시·나머지 검사 경로

`validation_04_execution_paths.py`는 재시도의 시험 조건 유지와 저장 작업 재사용을 담당하고,
`validation_05_special_fixtures.py`는 기동·입력 임피던스·과부하 및 직접 작성한 기준 회로의 기대 조건을 구성한다.

### 재시도

- 기본 경로와 재시도 경로를 모두 실행 전에 검사한다.
- 전원·부하·입력·해석 조건·측정 정의의 변경은 수치 해석 실패와 구분하여 차단한다.
- 허용되는 차이는 solver 선택, 강제 초기조건이 아닌 nodeset 추정, 저장 신호 선택이다.
- 나머지 소자/명령과 수치 오차 설정은 유지해야 한다. 숨겨진 소자를 추가하거나 허용 오차를 완화하는 재시도는 거부한다.
- 조건 오류를 다른 solver로 재시도하지 않는다. 실제 수치 해석 실행 오류에 대해서만 기존 재시도를 수행한다.

### 캐시

- 데크, 계획/계약, 실제 소비 측정 인자, include 모델과 하위 include 내용, 현재 검사 코드의 서명을 함께 확인한다.
- 과거 판정은 재사용하지 않는다. 검증된 raw/log를 가져온 뒤 현재 코드로 다시 측정·판정한다.
- 저장된 scalar 측정값도 실제 로그를 다시 파싱한 결과와 일치해야 한다.
- 필수 데크/raw/log 파일이 없거나 해시가 다르면 재사용하지 않는다.
- 실행 계약이 없는 이전 캐시는 새로운 검증 캐시의 근거로 삼지 않는다.
- 다른 결과 폴더의 동일 모델은 경로가 아니라 내용과 하위 include까지 대조한다. 임의의 다른 모델은 허용하지 않는다.
- 계산 조건이나 코드가 달라지면 보수적으로 재실행한다. 파일명/경로만 같다고 같은 작업으로 보지 않는다.
- 완료된 파이프라인 재개도 검사 코드 서명을 확인한다. 과거 완료 실행의 서명을 바꿔 강제로 재개하지 않는다.

### 추가 연결 경로

- 기동: 실제 전원 램프, 부하, DUT 단자 연결, 관찰 시간과 사용 정책을 검사한다. 조건 오류는 단순 기동 수렴 실패로 숨기지 않는다.
- 입력 임피던스: 두 입력 모드의 자극 식, 해석 범위, 부하 및 실제 R/C 피팅 정책을 검사한다.
- 과부하: 입력 과구동/복귀 파형, -10배 저항 피드백, 오차 밴드와 실제 소비 profile을 대조한다.
- 직접 작성한 위상여유/잡음/입력 저항 기준 회로에도 독립적인 기대 조건을 연결했다.

별도 과거 진단 스크립트 전체나 모든 SPICE 표현식까지 범용적으로 검증한다는 의미는 아니다.
이번 범위는 현재 통합 검증 파이프라인과 명시한 확장 경로다. PDF 원문 해석 정확도나 DUT의 모든 물리적 특성을 증명하는 작업과는 구분한다.

## 후속 보완: 잡음 소스 저항 반영

위에서 발견한 TL071C 입력 저항 20Ω 누락은 후속 작업에서 보완했다.
일반 잡음 fixture는 계획의 source_resistance_Ohm을 입력 전압원 VIN과 DUT 사이에 직렬로 배치하고,
VIN을 기준으로 환산한 총 입력 잡음 밀도를 측정한다. 저항 열잡음은 포함하며 임의로 차감하지 않는다.
측정 주파수도 계획의 frequency_Hz를 사용한다. 소스 저항이 누락되거나 우회되면 계약 오류로 차단한다.

기준 회로의 20Ω/200Ω 및 25°C/50°C 열잡음이 sqrt(4kTR)과 일치하는 것을 실제 LTspice로 확인했다.
기존 DUT의 측정은 약6.837nV/√Hz @1kHz이고, 일반 MOS 모델의 잡음 정확도가 보정되지 않아
판정은 unverified_model이다. 최신 코어 검증은 12개 통과,3개 모델 미검증,검사 오류0개다.
이것은 추가 정착시간 실패나 모든 원문 사양의 해결을 의미하지 않는다. 과거 보고서는 덮어쓰지 않았다.
