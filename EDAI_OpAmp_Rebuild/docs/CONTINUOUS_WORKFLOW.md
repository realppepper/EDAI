# 회로·하네스² 연속 운영 루프

## 연결 범위

`harness_07_workflow.py`가 기존 고정 회로 수정 루프를 여러 회차 연결한다. `run_opamp_workflow.py`가 진입점이다. 이전 `run_harness2_loop.py`의 대조 분기를 매번 실행하는 효과 비교가 아니다.

```text
현재 회로 + 목표/검사 계획 + 유효한 전체 측정 체인 + 현재 지침
 → 미달 없으면 종료
 → 지침 유지 또는 조건부 변경안 하나
 → 해당 고정 지침으로 회로 수정·전체 검증 반복
 → 회차 종료 시 모든 새 후보를 검사
 → 안전한 개선 후보가 있으면 회로·시험한 지침 전체를 쌍으로 보존
 → 없으면 이전 쌍 유지
 → 성공하면 종료 / 회차 예산이 남으면 선택한 쌍으로 다음 회차
```

현재 인터페이스에서 설계·지침 응답은 채팅이 맡고, 상태 전환·검사·보존·재개는 코드가 담당한다. 모델 API 전송은 추가하지 않았다. 호스트가 만든 요청 JSON과 응답 형식을 그대로 API 전송 계층에 연결할 수 있다. 기존 PDF→사양→HKG/PDG→검사 계획 산출물과 이미 생성한 회로/측정 체인을 입력으로 사용한다. 새 최초 토폴로지 생성 기능이나 미검증 검사 확대를 추가한 작업은 아니다.

## 세 가지 완료 조건

1. **연속 반복**: 내부 회로 루프의 여러 수정과 바깥 지침 회차를 모두 지원한다. 미달이면 다음 요청을 생성한다. 성공·회차 예산·잘못된 응답 한도에서 종료한다.
2. **선택/보존 연결**: ACTIVE/BEST는 항상 같은 회로·지침·측정 쌍이다. 회차의 마지막 후보가 악화됐어도 앞선 검증 후보를 보존한다. 거부한 지침을 다음 회차에 주입하지 않는다.
3. **연속 실행 확인**: 자동 검사에서는 실제 파일 요청/응답 경로와 상태기를 사용하고 EDA만 시험 결과로 대체한다. 실제 LTspice 확인은 별도 실행 보고서에 구분해 남긴다.

## 선택 기준과 효과 비교의 차이

필수 조건의 측정 전제가 유효하고, 현재 선택 회로의 통과 조건을 잃지 않으며, 실패 조건 집합이 엄격히 줄어든 후보만 회차 사이에 승격한다. 후보들 중 실패가 가장 적은 것을 선택하고 동률이면 앞선 선택을 보존한다. 정상 판정이 불가능한 조건을 가진 새 후보는 승격하지 않는다. 그 후보가 내부 회로 루프에서 추가 수정을 받는 것은 가능하다.

지침 변경 후 얻은 회로가 개선됐다는 이유로 시험한 지침을 함께 보존할 수 있지만, 이는 운영상 국소 선택이다. 같은 모델의 대조 실험을 한 것이 아니므로 그 지침 때문에 개선됐다는 효과 증거는 아니다. 새 지침을 합치거나 실패 후보의 메모리를 자동 병합하지 않는다. 원래 규칙과 검증 범위는 변경하지 않는다.

## 예산과 종료

- 기본값: 바깥3회차, 각 회차 회로 수정2회(최초 기준 후보 제외). 최대 새 설계6개.
- 지침 응답은 회차마다 유지(`proposals: []`) 또는 변경안1개.
- 성공은 현재 구현된 검사 범위에 한정된다. 전체 제조사 사양 성공은 계속false다.
- 측정 중단/재시도는 새 설계 시도로 계산하지 않는다. 같은 후보를 재개한다.
- 형식이 잘못된 지침 응답은 전체3회, 회로 응답은 기존 내부 실행기의 한도를 사용한다.
- 예산 종료도 정상 종료 상태이며 성공으로 표시하지 않는다. BEST는 남긴다.

## 실행

완료된 전체 검증 파이프라인이 있는 실패 회로에서 시작한다. 부분 측정 묶음을 전체 기준으로 가져오지 않는다. 원래 체인의 회로·코드·사양·교정·측정 해시를 검사한다.

```powershell
python run_opamp_workflow.py start --session runs/workflow/my_run --baseline-pipeline <validation 폴더> --netlist <같은 회로.inc> --max-rounds 3 --revisions-per-round 2
```

`NEXT_ACTION.json`의 actor가 `chat_improver`이면 연결된 `PROPOSE_REQUEST.json`으로 지침 응답을 만든다. 요청 ID, 요청 파일 SHA256, reason, proposals만 반환한다. proposals는빈 목록 또는 기존하네스² 형식의 변경안1개다. 실제 도구/예산이 요청에 표시되므로 사용할 수 없는 진단을 이미 수행한 것처럼 지시하지 않는다.

```powershell
python run_opamp_workflow.py propose --session runs/workflow/my_run --response <지침 응답.json>
```

actor가 `chat_designer`이면 해당 내부 `REQUEST_###.json`의 response_schema로 회로 응답을 만든다. 완전한 ASCII 넷리스트와 정확한 요청 ID를 반환한다.

```powershell
python run_opamp_workflow.py submit --session runs/workflow/my_run --response <회로 응답.json> --defer-validation
python run_opamp_workflow.py resume --session runs/workflow/my_run --ltspice <LTspice.exe>
```

검증 후 코드가 자동으로 다음 회로 요청 또는 다음 지침 요청을 만든다. 사용자가 별도로 ‘다음 회차’를 요청할 필요는 없다. 현재 채팅 실행자가 다음 actor에 맞는 응답을 계속 공급하면 같은 세션이 이어진다. 이 응답 공급을 프로세스 단독으로 무인 실행하는 모델 API는 아직 연결하지 않았다.

```powershell
python run_opamp_workflow.py status --session runs/workflow/my_run
```

## 저장과 복구

- `STATE.json`: 권위 있는 진행 상태. 다음 작업과 라운드/회로/응답 연결을 저장한다.
- `ACTIVE.json`, `BEST.json`: 같은 선택 쌍. 완료 후 resume으로 화면 파일을 재생성해도 시뮬레이션을 추가하지 않는다.
- `NEXT_ACTION.json`: 다음 담당 역할과 정확한 요청 경로/해시.
- `round_###/PROPOSE_REQUEST.json`, `PROPOSAL_RESPONSE.json`, `harness.json`: 지침 버전과 근거.
- `round_###/loop/`: 기존 회로 루프 원본 상태, 후보, 응답, 전체 검증 결과.
- `round_###/DECISION.json`: 해당 회차의 모든 후보 결과와 선택/거부 근거.

검증은 정상 Windows 실행 환경에서 진행한다. 중단됐다면 같은 세션의 resume으로 재개한다. 이미 접수된 같은 응답을 재전송해도 회차/검증을 중복 생성하지 않는다. 모델·사양·코드·결과 파일을 변경하면 동결 검사가 막는다. 이전 실험이나 기본 지침 파일을 덮어쓰지 않는다.

## 검증 범위

자동 검사는 여러 내부 수정, 두 외부 회차의 정책/회로 전달, 나쁜 후보·지침 배제, 더 좋았던 중간 후보 보존, 성공·예산 종료, 측정 중단/재개, 같은 응답의 중복 제출, 완료 후 재개, 미검증 항목 통과 방지, Windows 원본 바이트/요청 텍스트 해시 차이를 포함한다.

실제 측정 실행 결과와 기능 재현 한계는 `runs/harness_workflow/20261115_continuous_loop/REPORT.md`에서 확인한다. 알려진 부분 개선→성공 경로를 사용한 기능 재현은 새로운 설계 능력이나 하네스 효과 실험이 아니다.
