# 2026-11-16 갱신 내용

## 실행 흐름

PDF 전체 탐색/페이지 분류 → Nemotron Parse → 원문 행+LLM 의미 보완/대조 → HKG·PDG → 목표/검사 계획 → 이력 없는 최초 설계 → LTspice 전체 검사 → 고정 하네스 수정/연속 하네스² → 채택/회귀 방지/한도 종료 → 성공 시 스케마틱 저장.

설계와 의미 검토 판단은 현재 채팅/에이전트 JSON 응답이다. 설계 모델 API, UI와 블록 조합의 통합은 아직 안 했다. 하네스² 제어기가 있다고 지침 변경을 반드시 채택하는 것은 아니다. 최근 비-folded 실험은 `proposals=[]`로 지침을 유지하고 회로만 수정했다.

## 결과와 현재 한계

초기80조건과 확대103조건은 다른 시험 표본/정책이므로 수량만 직접 비교하지 않는다. 확대 계획은32사양 행을 여러 시험 조건으로 펼친103사례이며74조건이 현재 구현 범위,29조건이 미검증이다. 별도 프로젝트 기동7조건이 있다.

folded 기반 확대 회로는74/74·기동7/7. 이력 없는 설계자의 비-folded 회로는 최초47통과 → 수정 후57 →69 → 추가 수정69 →71/74·기동7/7까지 개선됐다. 최종3미달은9/24/36V high 방향 과부하 회복이다. 두 구조의 초기 이력/설계 예산이 달라 공정한 토폴로지 우열 비교는 아니다. [읽기 전용 예시](../examples/lm358b_20261116/README.md).

A 기본 피드백/B 고정 지침/C 하네스²의 별도 단일 파일럿에서는 독립 설계4개가 같은 수정안을 냈고 모두74조건+기동7조건을 통과했다. C는 동률이라 변경 지침을 미채택했다. 추가 지침의 이점, 토큰/시간 우위는 입증하지 않았다.

새 데이터시트에서 새 목표/검사 계획을 구성하지만 공학적 설정은 사용자가 선택한다. 범위 조건은 양끝점+범위 안 후보 전압만 선택하며 명시적 시험 전압은 유지한다. 중간 대표점을 새 범위에 맞게 최적으로 자동 선택하는 기능은 별도 보완 대상이다.

입력부터 완전 무인 API 실행을 입증한 것은 아니다. 이번 채팅 관리자는 초기 요청에 생략된 구체적 기동 계약과, 설계자가 요청한 자신의 이전 회차 상세 측정값을 전달했다. API 연결 전에 이 이관/도구 계약을 명확히 해야 한다. 일반 LEVEL1/25°C/단일 채널 조건이며 잡음·mismatch·제작/레이아웃·모든 PVT 성능을 보장하지 않는다.

과거 세션은 절대 경로/코드·입력 해시를 검사한다. 이 공유본의 예시는 로컬 run 캐시의 재개본이 아니므로 새 세션에서 시작한다. 대용량 파형·실행 로그·PDF/이미지·키는 배포하지 않는다.
