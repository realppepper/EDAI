# 반복 설계 이력 전달 구현

2026-11-15. 설계 루프의 다음 요청에 같은 실행 안에서 얻은 최근 수정 이력을 연결했다. **하네스²가 아니며 설계 지침은 자동 변경하지 않는다.**

## 전달 내용

최근 수정3회까지 다음 내용을 `iteration_history`에 넣는다.

- 변경 전후 후보 번호·회로/측정 파일 경로·해시
- 실제 넷리스트 차이와 LLM이 선언한 변경(별도로 구분)
- 같은 사양·같은 시험 조건에서의 측정값 변화와 단위·기준
- 새로 통과한 조건과 기존 통과에서 벗어난 조건
- 측정 미완료·전제 미충족으로 수치 비교가 불가능한 상태

직전 회로와 결과는 계속 기존 입력으로 전달한다. 이력은 추가 정보이다. 첫 후보에서는 수정 이력이 없으므로 빈 목록이다. 중간 실행 실패도 기록하지만 측정이 없는 후보와의 성능 변화량은 만들지 않는다.

목표·시험 조건·지표 정의가 다르거나 회로/측정/응답 파일의 해시가 달라지면 이력을 거부한다. 측정 결과가 해당 회로에 연결됐는지도 확인한다. 유효하지 않았던 측정값을 새 측정과 빼서 ‘개선’으로 표시하지 않는다. 변화량은 관측 사실이며 물리적 원인 확정이 아니다.

전체 넷리스트 차이가16000자를 넘으면 명시적으로 잘림을 표시하고 원본 후보 경로를 유지한다. 오래된 후보는 최근3회 수정 범위 밖으로 제외하며 제외 개수도 표시한다. 다른 과제나 과거 성공24pF 정답을 숨은 설계 예제로 추가하지 않는다.

## 코드와 버전

- `opamp_pipeline/harness_05_history.py`: 고정된 후보 아티팩트를 읽고 실제 차이·유효한 측정 변화·상태 변화를 구성한다.
- `harness_03_loop.py`의 `prepare`: 다음 `REQUEST_###.json`에 이력을 붙인 뒤 전체 요청의ID/해시를 다시 계산한다.
- `harness_02_request.py`: 새 정책의 이력 설정과 입력 형식 버전을 표시한다.
- `harness/fixed_v3_history.json`: 기본 정책. 최근3회 이력 활성화. 기존C1~C8의 지침 문구와 검증 가능 항목 목록은v2와 같다.
- `harness/fixed_v2.json`: 기존 비교 기준으로 그대로 보존. `--harness harness/fixed_v2.json`을 지정하면 이력 없는 형식v2 요청을 만든다.

일반 검증 파이프라인의 `DESIGN_REQUEST.json`은 한 후보만 알고 있다. 여러 후보의 이력은 **설계 루프의 `REQUEST_###.json` 생성 시점**에 연결한다.

새 루프 세션부터 적용한다. 코드가 바뀌었으므로 이전 코드로 동결한 세션을 그대로 재개하지 않는다. 기존세션·실험·58조건 재검증 결과는 보존한다. 회로·EDA 검사기·목표·성공 기준·최선 후보 선정 방식은 변경하지 않았다.

## 검증

전체 자동 검사224개 통과. 정상 측정 변화, 무효한 이전 측정, 실행 실패, 최근 이력 제한, 목표·조건·파일 변조, 실제 루프 요청 연결과 해시, v2 보존과 하네스² 비활성 등을 확인했다.

저장된 한 설계 실행의80pF→32pF 후보 쌍으로 오프라인 입력 생성도 확인했다.

- 실제 Ccomp 변경이 넷리스트 차이에 포함됐다.
- 같은5V 대역폭의0.984MHz→2.433MHz 변화량이 전달됐다.
- 과거36V 회복 시간이 측정 전제 미충족이었던 경우에는 숫자 개선으로 계산하지 않았다.
- 같은 현재 후보의v2/v3 요청에서 목표·현재 피드백·평가 범위는 같고, v3에 이력만 추가됐다(버전·ID 등 메타데이터 제외).
- 과거 세션을 재개하거나 결과를 덮어쓰지 않았다. 예제는 읽기 전용 자료로 만든 요청 샘플이며 실행 가능한 세션이 아니다.

근거: `runs/harness_improvement/20261115_iteration_history/CHECKS.json` 및 `demo/v2`, `demo/v3`의 `REQUEST_002.json`. 변경 전 코드는 같은 폴더의 `baseline`에 저장했다.

새 시뮬레이션·설계용API 호출·하네스²·자동 모델 전환·Git push는 실행하지 않았다. 이 기능이 성공률이나 반복 횟수를 개선하는지는 아직 검증하지 않았다. 이력이 생긴 뒤부터 차이가 발생하므로 효과 평가는 동일한 기회와 대화 이력 조건을 맞춘 여러 회차 설계에서 해야 한다.


## 실제 설계 활용 확인 추가

기존80→32pF 이력을 명시적으로 가져온 별도 기능 점검에서 현재 채팅이 이력을 참고하여 Ccomp를23.5pF로 제안했다. 새 후보를 LTspice로 검증해 구현된58조건 모두 통과했고22조건은 미검증으로 유지했다. 검증 후 이력 생성에서 동일 지표가 두 구간/한 구간으로 저장되는 차이를 발견했다. 목표와 지표 정의가 같을 때 구간 수 변화는 명시적으로 표시하고 숫자 비교는 생략하도록 보완했다. 서로 다른 목표·조건·단위·한계값은 여전히 거부한다. 전체 자동 검사226개 통과.

이전 두 후보는 현재v3로 생성한 결과가 아니며 설계자는 기존 성공 사례도 알고 있어 효과 비교로 해석하지 않는다. 원래 실행의 상태/코드 서명은 보존했다. 상세 근거: `runs/harness_improvement/20261115_iteration_history/live_usage_check/REPORT.md`.
