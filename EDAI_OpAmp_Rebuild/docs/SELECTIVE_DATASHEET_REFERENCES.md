# 데이터시트 참고자료를 필요한 경우에만 전달

사양표에서 확정한 설계 목표/검사 조건은 계속 필수 입력으로 사용한다. 동작 설명·기능도·특성곡선·응용 예시 등은 별도의 선택적 참고 경로이다. 참고자료 전체를 매 요청에 넣지 않는다.

1. 최초 설계/수정 요청에는 선택적 도구 설명과 참고 페이지 목록 파일의 위치만 넣는다. 페이지 본문과 이미지는 기본 요청에 포함하지 않는다.
2. 현재 설계 역할이 구체적인 필요성을 판단한다. 단순 사이징이면 `needed:false`로 건너뛴다. 구조 선택/입력 범위/출력 구동/안정성 등 이해가 필요할 때만 페이지별 이유와 관련 조건을 적어 선택한다.
3. 한 요청에서 최대2쪽, 텍스트 합계 최대4000자를 전달한다. 이는 문자 제한이며 토큰 보장은 아니다. 선택한 원본 페이지 이미지 경로·해시·출처도 함께 제공한다.
4. 그림/곡선을 참고하려면 설계 역할이 실제 이미지를 열어 봐야 한다. 파싱된 그림 속 글자는 회로 연결/곡선 형상을 검증한 데이터가 아니다. 현재 채팅에서는 이미지 보기 도구로 확인한다. 향후 API 전송에서는 별도의 이미지 전송을 연결해야 하며, 경로 문자열만으로 모델이 그림을 읽었다고 주장하지 않는다.
5. 참고자료가 붙은 새 요청 파일을 만들고 기존 요청은 보존한다. 목표·회로·검사 조건·수정 예산은 유지한다. 이후 설계 응답에는 사용한 페이지/문단/이미지 확인 여부/적용 내용 또는 사용하지 않은 이유를 기록한다. 사용 기록은 설계자의 선언이며 실제 성능 이점은 시뮬레이션으로 따로 확인한다.

실제 제품의 BJT 기능도는 일반 MOS 모델에서 그대로 구현할 구조가 아니다. 구조 아이디어와 동작 이해를 위한 참고이며 복제를 강제하지 않는다. 응용회로는 외부 사용 예시일 수 있고, 다른 제품/다른 온도의 특성은 자동 목표가 아니다. Typical 곡선의 파싱된 추정 수치는 이 경로에서 텍스트로 전달하지 않고 합격 기준에도 추가하지 않는다.

## 사용

현재 설계자는 채팅이 담당한다. 다음 결정 파일은 도구 요청 예시이다.

```json
{
  "source_request_id": "현재 request_id",
  "needed": true,
  "reason": "동작 구조를 참고할 구체적인 이유",
  "pages": [
    {"pdf_page": 25, "reason": "동작 설명과 기능도를 참고", "case_ids": []}
  ]
}
```

`needed:false`이면 이유만 적고 페이지를 선택하지 않는다. 외부 호출/본문 전달은0이다.

```powershell
python run_datasheet_references.py prepare --request <현재요청.json> --decision <선택.json> --supplement <새보조자료.json>
python run_datasheet_references.py attach --session <루프세션> --supplement <보조자료.json> --kind fixed
```

최초 회로 생성 대기 상태라면 `--kind initial`을 사용한다. 반드시 새 `pending_request` 파일을 설계자에게 전달한다. 이전 요청 ID를 사용한 응답은 거부된다.

원본 페이지 인덱스가 없는 파생 검사 계획 폴더는 자동으로 다른 실행을 뒤져 연결하지 않는다. 필요할 때 같은 PDF/제품의 원래 파싱 문서 폴더를 명시적으로 연결할 수 있다. 이 단계는 목록만 연결하며 본문을 전달하지 않는다.

```powershell
python run_datasheet_references.py catalog --session <루프세션> --document <원래파싱문서폴더> --kind fixed
```

PDF 원본·목록·선택 페이지 파싱·이미지 해시를 검사하고, 전달 텍스트는 원본 파싱 블록 위치와 대조한다. 해시를 재계산한 조작 발췌도 원본과 다르면 거부한다. 이전 실험에 소급 적용하지 않으며 비교 실험에서 참고자료 정책을 바꾸려면 사전에 실험 조건으로 정해야 한다.
