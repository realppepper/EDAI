# 피드백 전달 보완 — 2026-11-15

## 범위의 의미

‘현재 평가 범위의 필수 항목’은 현재 구현된 검증 능력으로 성공을 판정하는 조건이다. 작업 순서나 긴급도를 뜻하지 않는다. 현재58개이며, 회로 때문에 측정 전제가 충족되지 않은36V 과부하 회복 검사도 포함한다. 이 항목을 제외한 채 성공으로 판정하지 않는다.

나머지22개는 모델·검사기 확장이 필요한 미검증 항목이다. 전체80개 요구사항에 유지하며, 통과 또는 목표 제외로 처리하지 않는다. 현재 범위의 성공과 최종 프로젝트 목표의 달성을 구분한다.

## 변경 내용

- `harness_04_feedback.py`: 호스트와 요청 생성기가 같은 검증 능력 목록으로 범위를 결정한다. 사례마다 필수 여부, 판정 유효성, 후속 조치를 표시한다.
- `harness_02_request.py`: 요청 형식v2에 전체 범위와 필수 미해결 목록을 추가한다. 세부 검사에 기록된 경고·측정 근거·수치 판정·실행 완전성·재시도 기록을 전달한다. 기존 목표·시험 조건·수치·사례ID는 유지한다.
- `harness_03_loop.py`: 중복된 범위 계산을 공통 함수로 연결했다. 성공 기준·시뮬레이션 예산·후보 선택 방식은 바꾸지 않았다.
- `verify_05_overload_recovery.py`: 기존 정지 상태 판정의 측정값과 한계값을 구조화한다. 기존계산과임계값은 동일하다.36V에서0.72V는 프로젝트 측정 전제 기준이며 데이터시트 목표가 아니다.
- `harness/fixed_v2.json`: 근본적인 모델·검사기 한계와 현재 후보의 측정 전제 미충족을 구분하도록C1-2를 보완했다. 이전fixed_v1은 보존한다. Harness² 및 외부 설계API는 여전히 비활성이다.

새 기본 지침은v2이다. 소스와 지침이 변경되었으므로 이전에 동결한 세션을 그대로 재개하지 말고 새 세션을 생성해야 한다. 과거 실험은v1 결과로 보존한다.

측정 전제가 충족되지 않은 경우에도 기존 숫자는 남기되 진단용으로 표시한다. 이 근거만으로 실패의 물리적 원인을 확정하지 않는다. 모순된 통과 상태는 요청 생성 시 거부한다.
