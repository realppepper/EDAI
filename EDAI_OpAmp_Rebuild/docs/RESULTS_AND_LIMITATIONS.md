# 실제 결과·정정·한계

## 현재 근거

| 항목 | 확인한 범위 |
|---|---|
| 원문/목표 | LM358B의 사양 42행 관리, 프로젝트 범위 32행 → 80조건 |
| 회로 | 일반 GNM/GPM MOS 모델, 한 물리 채널, 25°C |
| 엄격한 전체 검사 | 18pF 회로 58통과 / 22미검증 |
| 입력 범위 | 3·5·15·36V에서 각각 원래 201지점 확인 |
| 코드 검사 | 원래 환경 192통과. 공유본은 186통과, 로컬 원문 관련 6개 건너뜀 |
| 안정화 | 실제 Windows 읽기 잠금, 오류 주입, 최초 저장·재개, 같은 후보 복구, best/report 재구성 |

대표 결과는 [examples](../examples/lm358b_25c/README.md)에 축약했습니다. 전체 파형·실행 해시가 들어 있는 원래 run 캐시는 Git에 포함하지 않았습니다. 예시는 원본 검증 기록의 요약이지 독립적인 원문 전체 검증이나 재개 가능한 체크포인트가 아닙니다.

## DC 누락 판정 정정

이전18pF의 36V 검사에는 요청한 201점 중 179점, 15V에는 194점만 있었습니다. 남은 점의 오차만 보고 통과시키던 버그였으므로 예전58통과는 당시 데이터만으로 두 조건의 완료를 뒷받침하지 못합니다.

누락·중복·범위 확인과 중앙 분할/수치 오류 재시도를 추가한 뒤 동일 회로를 새로 전체 검증했습니다. 현재의58통과는 그 새 검증과 안정화 재현을 근거로 합니다. 15/36V 분할 진단을 각각 두 번 반복했고 모든 점과 같은 측정값을 확인했습니다. 3V에서는 누락을 감지한 뒤 원래 전체 스윕으로 재시도해 201점을 확인했습니다. 유효한 성능 미달을 다른 계산으로 덮어쓰는 재시도는 허용하지 않습니다.

## 고정 지침 단회 비교

같은 초기80pF 회로와 같은 새 검사기에서, 대화 이력 없는 에이전트 둘에 수정 기회를 한 번씩 줬습니다. 한쪽에만 고정 설계 지침 텍스트를 추가했고 공통 실행/제약/구조화된 피드백은 유지했습니다.

| 조건 | 수정 | 통과 | 남은 미달 | 36V high/low 회복 |
|---|---|---:|---:|---|
| 기본 피드백 | Ccomp32pF |57|1|13.12 / 11.94µs|
| 지침 추가 | Ccomp35pF + M5 폭50% 증가 |57|1|14.55 / 13.12µs|

회복 목표는 방향별10µs 이하이며 둘 다 만족해야 한 조건이 통과합니다. 기존22개 미검증은 그대로입니다. 이번 과제에서는 지침의 통과 수·성공 여부 이점이 확인되지 않았습니다. 단일 과제/제안이므로 일반적인 효과 유무를 결론 내릴 수 없습니다. 모델 설정은 같은 부모를 상속했지만 정확한 런타임 모델 식별자는 별도로 기록하지 않았고, 토큰·비용도 측정하지 않았습니다.

지침 조건에서 Windows 결과 저장 접근 거부가 발생해 관리자가 같은 후보의 하위 검증을 재개했습니다. 새 설계안은 없었고 최종 측정 오류는0이지만 무오류·무인 실행으로 주장하지 않습니다. 이후 저장 재시도와 자동/수동 재개를 코드로 보완하고192검사와 실제18pF 검증으로 확인했습니다. 그 안정화 확인은 새 하네스 비교 실험이 아닙니다.

## 미검증 22조건

| 한계 | 사례 수 | 내용 |
|---|---:|---|
| 모델·해석 |15|입력 바이어스3, 오프셋 전류3, 잡음 밀도3, 차동 입력 임피던스3, 공통모드 입력 임피던스3 |
| 검사기 미구현 |7|채널 분리3, 저주파 peak-to-peak 잡음3, THD+N1 |

공통모드 입력 C 등 일부 하위 측정이 있어도 해당 R/C 전체 사양의 통과로 바꾸지 않습니다. LEVEL1 모델의 이상적인 게이트 누설, 미보정1/f 잡음·mismatch는 실제 IC 정확성을 보증하지 않습니다.

## 아직 주장하지 않는 것

- LM358B 내부 회로 복제, TI PDK나 제조용 레이아웃/내압/공정 검증.
- 온도·공정·부하 연속 범위 전체, 모든 입력에서 독립 냉간 기동의 검증.
- 그래프의 모든 수치 추출·승인, 원문 전체 의미의 자동 무오류 판정.
- 완전 무인 설계 API, 자동 모델 선택/토큰 절감, Harness² 효과.
- 블록 조합과 UI가 이미 이 루프에 통합됐다는 주장.

다음 연구는 어떤 실패를 어떤 지침/피드백 개선으로 줄일지 가설을 정하고, 같은 예산의 과제·반복으로 확인하는 것입니다.
