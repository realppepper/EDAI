# 구조 결정 모델 (FLAN-T5 구조 생성)

작성: 김지윤 · 2026-11-11 · 브랜치 `feature/jiyun-opamp-design-loop`

데이터시트 목표값을 글 한 줄로 넣으면, OP-Amp 회로 구조(소자 연결 표)를 글로 써 내는 모델입니다. 구조 후보를 여러 개 만들고, 크기 정하기와 ngspice 판정을 거쳐 하나를 고르는 파이프라인의 첫 단계입니다.

## 2. 입력과 출력

**입력**: 목표 항목을 `이름 값 단위`로 이은 한 줄. 항목은 일부만 있어도 됩니다.
```
op-amp spec: avd 103 dB; cmrr 94 dB; psrr 114 dB; idd 300 uA; ugbw 1.2 MHz; sr 0.5 V/us; pm 56 deg; voh_1ma 3.6 V; voh_5ma 3.5 V; vol_1ma 0.75 V; io_source 30 mA; io_sink 20 mA
```
항목 이름 15개: `avd cmrr psrr idd ugbw sr pm gm ts voh_1ma voh_5ma vol_1ma vol_5ma io_source io_sink` (정의는 `spec_tlv271.json`).

**출력**: 소자마다 이름과 단자별 연결 노드를 ` ; `로 이은 한 줄.
```
PM1 D=VB2 G=VB2 S=VDD B=VDD ; PM2 D=OUT G=N1 S=VDD B=VDD ; ... ; NM1 D=VB1 G=VB1 S=VSS B=VSS ; ... ; R1 P=N7 N=VSS ; C1 P=OUT N=N5
```
- 소자: `PM#`(PMOS, D G S B), `NM#`(NMOS, D G S B), `R#`, `C#`(P N)
- 고정 단자: `VDD`, `VSS`, `IN1`, `IN2`, `OUT`. 바이어스 단자 `VB#`(전압), `IB#`(전류)는 써도 됨. 그 밖은 내부 노드 `N#`
- 크기(W/L)는 출력하지 않습니다. 크기는 다음 단계(`auto_size.py`)가 정합니다.

## 3. 학습 데이터

| 단계 | 내용 | 파일 |
|---|---|---|
| 구조 모으기 1 | AnalogGenie 공개 데이터셋(ICLR 2025, 교과서·논문 회로 3,350개)의 OP-Amp 범위 568개 중, 트랜지스터·R·C만 있고 입력 2·출력 1·전원 2(+바이어스) 단자인 435개 | `opamp_dataset.py` → `data/opamp_tables.json` |
| 구조 모으기 2 | 직접 블록을 조립해 만든 OP-Amp 15종 | `blocks/`, `topology.py` |
| 크기 정하기 | 구조마다 gm/ID 방식으로 자동 크기 (GF180 6 V 소자, 전류원 20 µA, 출력단 1배·5배 두 가지) | `auto_size.py`, `label_dataset.py` |
| 측정 | ngspice 테스트벤치 5종으로 15개 항목 측정 (VDD 5 V, 부하 2 kΩ·10 kΩ, 10 pF) | `run_sim.py`, `tb_opamp_*.cir` |
| 거르기 | "동작"한 것만: 버퍼 출력이 2.5 V ± 0.5 V, 모든 트랜지스터 포화, 무부하 이득 20 dB 이상 | `label_dataset.py` |
| 결과 | 측정 줄 465개 (AnalogGenie 435 + 블록 30), 서로 다른 구조 243개 (228 + 15) | `data/labels_analoggenie_all.json`, `data/labels_blocks.json` |
| 문장 만들기 | 측정 줄마다 15개 항목을 다 쓴 문장 1개 + 항목 일부만 남긴 문장 3개 (항목마다 60% 확률로 남김, 최소 3개). 값은 유효숫자 3자리 | `make_train_data.py` |
| 나누기 | 구조 단위로 10%를 검증용으로 뗌 (같은 구조가 학습·검증에 함께 들어가지 않게) | `data/train/train.jsonl` 1,672문장, `val.jsonl` 184문장 (구조 24개) |

학습 구조 243개의 출처: AnalogGenie "opamp papers" 묶음 217개(논문 이름 표시 없음), 교과서 11개(Razavi, Gray, Allen·Holberg 등, 쪽 번호·원본 그림 있음), 직접 만든 블록 15개. 데이터시트는 학습에 하나도 쓰지 않았습니다(TLV271, LM358B는 시험용).

## 4. 학습

노트북: `colab/flan_t5_structure.ipynb` (2번 셀이 이 브랜치의 `data/train/`에서 학습 파일을 바로 받음)

| 설정 | 값 |
|---|---|

## 5. 검증 결과

학습에 없던 구조 24개의 스펙 문장(항목이 가장 많은 문장)을 넣고, 빔 4개로 하나씩 생성했습니다 (`data/train/model_eval.json`).

| 기준 | 결과 |
|---|---|
| 형식이 맞음 (소자 이름·단자 구성) | 24 / 24 |
| 규칙 검사 모두 통과 (단자 5개 있음, 입력이 게이트에 붙음, 떠 있는 노드 없음 등) | 22 / 24 |
| 정답 구조와 똑같음 | 0 / 24 |
| 학습 데이터에 있던 구조를 그대로 씀 | 17 / 24 |

해석: 회로로서 말이 되는 구조는 거의 항상 쓰지만, 처음 보는 스펙에는 학습 때 본 구조를 그대로 내는 경우가 많습니다.

## 6. 후보 생성 (데이터시트 시험)

`generate_candidates.py <부품>`: 빔 탐색 10개 + 무작위 생성 30개(top_p 0.95, temperature 0.8, 10개씩 3번), 같은 글은 하나로. 이 컴퓨터 CPU에서 약 6분.

| 부품 | 서로 다른 후보 | 규칙 통과 | 동작 (크기 정한 뒤) | 선택 |
|---|---|---|---|---|
| TLV271 (사람이 옮긴 스펙 15개) | 33 | 28 | 12 (새 구조 10) | 후보 32, 15개 중 8개 통과 |
| LM358B (박준석 측정 계획 12개) | 34 | 28 | 12 (새 구조 9) | 후보 1, 12개 중 7개 통과 (학습에 있던 구조) |

같은 판정 기준으로 학습 구조 243개를 재면 LM358B는 최고 7/12(14개 구조), TLV271은 최고 11/15(8개 구조)입니다. LM358B 선택 구조는 학습 구조 최고와 같은 수준이고, TLV271 선택 구조는 그보다 낮습니다. 결과 페이지: `docs/selection_lm358.html`, `docs/selection_tlv271.html`.

## 7. 로컬에서 실행할 때 주의

환경: WSL Ubuntu, `~/.venvs/edai` (Python 3.10, torch 2.5.1+cpu, transformers 4.46.3, sentencepiece).

```bash
~/.venvs/edai/bin/python generate_candidates.py lm358
```

**transformers 버전 차이 문제**: 모델은 Colab의 transformers 5.x로 저장되어 `config.json`에 `tie_word_embeddings: true`가 들어 있지만, 실제 출력층(`lm_head`)은 따로 학습되어 있습니다. 4.x로 그대로 읽으면 출력층을 입력 임베딩으로 덮어써서 "behörde fehler ..." 같은 엉뚱한 글만 나옵니다. `generate_candidates.py`는 `from_pretrained(..., tie_word_embeddings=False)`로 읽어 이 문제를 피합니다. 다른 코드에서 모델을 읽을 때도 같은 옵션을 넣어야 합니다.

## 8. 한계

1. **측정값이 한 가지 크기 정하기 방식에서 나왔습니다.** 모델은 "이 자동 크기로 만들면 이 성능이 나오는 구조"를 배운 셈이라, 크기를 최적화했을 때의 구조 성능을 반영하지 못합니다.
2. **새 구조를 잘 만들지 못합니다.** 검증에서 정답과 같은 구조 0개, 학습 구조 재사용 17/24.
3. **입력 항목 15개가 TLV271 특성표 기준으로 고정**되어 있습니다. 데이터시트의 다른 항목(오프셋, 잡음 등)은 입력으로 쓰지 못합니다.
4. **측정 조건이 5 V 하나**입니다. 데이터시트 조건(예: LM358B 이득·출력 전류는 15 V)과 다릅니다.
5. **OP-Amp 5단자 구조만** 만듭니다. 완전 차동, 끄기 핀 같은 추가 단자는 다루지 않습니다.
6. 학습 구조의 89%가 출처(논문 이름)를 확인할 수 없는 AnalogGenie 묶음에서 왔습니다.
