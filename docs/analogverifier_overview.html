AnalogVerifier 시스템 지도

데이터시트 PDF 하나를 넣으면 LLM이 특성표를 구조화하고, LLM 에이전트가 트랜지스터 회로를 써서 LTspice로 검증하고, 떨어진 항목을 보고 회로를 고쳐 쓰는 일을 반복하는 시스템입니다.

코드를 실행하지 않고 README, 핵심 모듈, LM358B 결과 파일, 커밋 기록을 읽어 정리했습니다.

2핵심 개념

HKG · Hardware Knowledge Graph하드웨어 지식 그래프

데이터시트를 구조화한 표. 줄마다 기호, 이름, min/typ/max, 단위, 측정 조건, 쪽 번호, 근거 문장. LM358B는 260줄(전기 특성 195줄).

PDG · Port Dependency Graph포트 의존성 그래프

핀 사이의 순서 관계. 목표 숫자는 없고 "어느 핀이 먼저 자리 잡아야 다음 핀이 의미 있나"를 담음. 검증 순서에 씀.

spec_planner측정 계획

특성 줄마다 측정 종류(예: aol_db 개방 이득, vswing 출력 스윙)와 조건(전원, 부하)을 붙임. 잴 수 없는 줄은 이유와 함께 제외.

Hermes Agent회로를 쓰는 LLM 에이전트

NousResearch의 오픈소스 에이전트 구조를 감싼 여러 턴 루프. 도구 6개: 설계도 찾기, 웹 검색, 문법 검사, 시뮬레이션 검증, 메모 기록, 설계도 저장.

Harness² · C1~C8LLM을 둘러싼 작업 환경

지침, 문법 규칙, 실패 메모, 도구 사용법, 회로 설계도, 스크립트, 보조 에이전트, 플러그인의 8칸. 반복할 때 회로만이 아니라 이 환경도 고침.

Golden Oracle검증 기준 지킴이

LLM이 검증 규칙을 바꾸자고 하면, 제조사 공식 모델(TI LM358, LM393 등)을 100% 통과할 때만 받아들임. 기준이 느슨해지는 것을 막음.

가장 중요한 아이디어: 4단계 순차 검증

앞 단계에서 떨어지면 뒤 단계를 재지 않고 0%로 처리합니다. 동작하지 않는 회로가 "출력이 낮으면 통과" 같은 항목으로 점수를 얻는 착시를 막기 위해 넣었습니다. 예전에는 입력과 출력이 끊어진 LM358 회로가 25%를 받았습니다.

반복할 때 고치는 방법: Propose–Probe–Compose

  1. 수정안 A(문법·수렴·접지 같은 안정성 규칙)와 수정안 B(소자 크기, 구조, 보상)를 LLM이 각각 만듭니다.
  2. 두 안으로 회로를 다시 써서 둘 다 시뮬레이션합니다.
  3. 통과 수가 더 높은 안을 다음 반복의 작업 환경으로 채택합니다.

LLM 사용

NVIDIA NIM, Groq, OpenRouter를 바꿔 쓸 수 있고, 작업마다 모델 크기를 나눕니다. 표 읽기는 작은 모델(4B급), 회로 합성은 중간 모델(30B MoE), 실패한 쪽 복구와 어려운 수리는 추론형 모델을 씁니다. 동시 요청은 4개로 제한합니다.

4성과와 한계

잘 되는 것

  1. 정보 추출: 8개 IC를 사람이 만든 정답과 비교해 평균 95.2점.
  2. 근거 추적: 줄마다 쪽 번호와 원문을 남기고, 원문과 다시 대조하는 감사 기능이 있음.
  3. 검증 설계: 4단계 순차 관문과 중복 줄 부풀리기 방지(고유 지표 통과율).
  4. 제조사 공식 모델로 검증기를 맞춤: TI LM393 16/16, NE555 28/28 오판 없음.

아직 안 되는 것

  1. LLM 단독 합성은 4단계 검증에서 모두 0%.
  2. LM358B 자동 실행은 핀 대응 실패로 측정 0줄.
  3. 설계도 라이브러리의 OP-Amp 칸에 실제 회로가 없음(경험 메모 1건).
  4. 일반 BJT/MOS 모델이라 실제 공정(PDK)과 차이. 크기는 LLM이 정하고, 수치 최적화는 과제로 남음. 사이징 규칙 칸(C6)은 비어 있음.
100% 통과 회로의 실체 (README에 직접 공개된 내용)

LM393, TL431, LM358의 100% 통과 회로는 오픈 모델이 혼자 만든 결과가 아니라, AI 코딩 도우미가 다이오드 방정식과 BJT 모델 수식을 직접 계산하고 디버깅해 다시 만든 것입니다. 이 회로를 "골든 설계도"로 저장해 다음 실행에서 LLM이 참고하게 하는 것이 설계 의도입니다.
