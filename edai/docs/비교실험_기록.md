# 구조 결정 방식 비교 실험 기록 (A·C·D)

작성: 2026-11-21 · 진행 중인 실험이라 결과가 나오는 대로 이어서 적는다.

## 1. 왜 하는가

FLAN-T5 구조 결정 모델이 실제로 쓸모가 있는지 확인한다. 모델을 핀 정보까지 넣어 다시 학습하기 전에,
지금 모델로 먼저 비교한다.

| 방식 | 첫 구조를 만드는 쪽 | 완성·채점하는 쪽 |
|---|---|---|
| A (하네스만) | 박준석 시스템 (LLM) | 박준석 시스템 |
| C (모델 + 하네스) | 우리 FLAN-T5 | 박준석 시스템 |
| D (찾기 + 하네스) | 우리 학습 데이터에서 스펙이 가까운 구조 찾기 | 박준석 시스템 |

- 최종 점수는 셋 다 박준석 시스템이 매긴다. 우리 쪽 숫자(ngspice)는 "하네스에 넣기 전" 참고값으로 따로 표시한다.
- D를 넣은 이유: C가 좋게 나왔을 때 모델이 잘 만들어서인지, 학습 데이터 구조가 원래 좋아서인지 가르기 위해.

## 2. 공정하게 맞춘 조건

1. **같은 출발 라이브러리**: 박준석 시스템은 실행이 끝날 때마다 배운 경험을 `harness2_library/`에 저장하고 다음 실행에 쓴다.
   A·C·D 모두 박준석이 커밋한 상태(4d1e221, 2026-11-06)에서 시작하고, 각 방식 안에서는 칩을 돌릴수록 쌓이게 둔다.
   A가 배운 라이브러리는 따로 보관한다.
2. **같은 데이터시트 분석 결과**: C·D는 A에서 시스템이 만든 HKG를 시스템의 재사용 기능
   (`output_interactive/.hkg_cache/`)으로 다시 쓴다. 같은 핀·스펙에서 출발하게 하기 위해.
3. **같은 실행 조건**: Web Studio와 같은 요청(업로드 → 실행), 반복 5회, LLM은 NVIDIA NIM.
4. **같은 후보 예산**: C는 FLAN-T5가 40개 써서 서로 다른 후보 30개 안팎, D는 가까운 구조 30개.
   고르기는 같은 코드(`select_structure.py`)와 같은 판정 항목으로 한다.

## 3. 칩

Drive `테스트 시나리오` 폴더의 데이터시트 96개 중 4개: OPA320, OPA2376, MCP6441, TLV271.
시간 때문에 **OPA2376, TLV271 두 칩을 먼저** 정확히 하고, OPA320·MCP6441은 밤에 같은 순서로 돌린다.
두 칩 결과로는 통계적 결론을 내지 않는다 (칩 수가 적어 우연과 구분되지 않음). 큰 차이가 있는지 보는 사례로 쓴다.

## 4.10 바이어스 교체 결과와 발견 (2026-11-21 밤)

| 칩 | 방식 | 교체 방법 | 교체 전 → 후 통과 | 상태 |
|---|---|---|---|---|
| TLV271 | C | 다이오드, 두 노드 1 mV 안 | 4/5 → 4/5 | 성공 (소비전류 570 → 573 µA) |
| TLV271 | D | 전류 주입, 동작점 0.9 mV 안 | 4/5 → 2/5 | 실패 (측정 회로에서 이득 73 → 6 dB) |

- 실패한 회로는 바이어스 노드가 회로 안의 자기 바이어스 고리(β-multiplier 꼴)에 묶여 있다.
  원래 회로에서는 이상 전원이 startup과 전압 고정을 대신했다. 값만 맞추는 교체는 다른 안정점으로 넘어간다.
- 박준석 시스템은 칩 안의 독립 전압원·전류원을 둘 다 금지한다 (`deterministic_testbench.py` PDG_STAGE0_INTERNAL_SOURCE).
- **학습 구조 243개 중 210개(86%)가 바이어스를 밖에서 받는 단자(VB 207, IB 5)를 갖는다.** 스스로 바이어스하는 구조는 33개.
  → 실제 칩 회로로 쓰려면 바이어스 회로를 만드는 단계가 거의 모든 회로에 필요하다.
- 결정: 값 맞추기식 교체 대신 **바이어스 변환기를 제대로 만든다** (4.11). 두 칩 C·D 비교는 변환기가 나온 뒤 다시 한다.

## 4.11 전체 흐름과 바이어스 변환기 설계 방향

```
 [1] 데이터시트 분석      박준석 시스템 (HKG, PDG, 측정 계획)
 [2] 코어 구조 결정       FLAN-T5 모델 (또는 학습 데이터 찾기)        ← A·C·D 비교 대상
 [3] 크기 정하기          gm/ID + GF180 (auto_size)
 [4] 바이어스 회로        변환기 → 미해결이면 하네스 → 검사          ← 새로 만듦
 [5] 핀 기능 조립         규칙 (채널 복사, SHDN, NC, 전원 핀)         ← 아직 없음, [4]와 같은 방식 예정
 [6] 완성·개선            박준석 하네스 (스펙 맞추기 반복)
 [7] 최종 판정            박준석 시스템 검사 (+ 우리 ngspice)
```

[4] 바이어스 변환기 방식 ("규칙이 기본, 모르는 경우만 하네스, 성공하면 규칙으로 승격"):
1. 변환기: 회로마다 기준 전류 하나 (β-multiplier + startup, 전원 전압에 거의 무관) → 전류 미러로 각 VB·IB에 분배.
   게이트만 붙은 VB는 미러 전류 + 다이오드로 전압 생성, 알려진 고리 모양은 그 고리를 기준으로 쓰고 startup만 추가,
   모르는 모양은 "미해결" 표시.
2. 검사 (변환기·하네스 공통): 동작점 2 mV 안, 측정값 비교, 전원 켜기(0 → 5 V 과도) 시험, 박준석 첫 관문 규칙.
3. 하네스: 미해결 노드만 좁은 과제로 박준석 하네스 부품(Hermes, NIM, 경험 라이브러리)을 직접 불러 맡긴다.
   채점은 2번 검사(ngspice + GF180)로 하고, 실패 이유를 돌려줘 반복한다.
4. 승격: 하네스가 성공한 모양은 변환기 틀과 박준석 라이브러리 설계도 노트(c5 skill)에 추가한다.
5. 순서: 변환기·검사 → 학습 구조 243개에 돌려 미해결 수 세기 → 많으면 하네스 연결 → 두 칩 C·D 비교 다시.

## 4.12 바이어스 변환기와 다시 고르기 (2026-11-22)

**바꾼 방식**: 고른 뒤 덧붙이던 방식(4.6, 4.10)을 버리고, **크기를 정하기 전에** 바이어스 단자를 실제 소자로 채운다
(`bias_convert.py`, `auto_size.py` `bias_mode="devices"`, `select_structure.py --bias-devices`).
이상 전원이 있는 상태로 다른 소자 크기를 맞추면 나중에 무엇으로 바꾸든 크기가 어긋나기 때문.

| 분류 | 판단 기준 (연결만 봄) | 처리 |
|---|---|---|
| 스스로 바이어스 | 노드에 다이오드 연결 소자나 저항이 있음 | 아무것도 안 붙임 |
| 빈 다이오드 채움 | 다른 소자 드레인이 전류를 넣는데 받을 다이오드가 없음 | 다이오드 소자 1개 |
| 기준 전류 + 미러 | 게이트에만 붙은 VB, 또는 IB | β-multiplier 기준 회로 1개(`bias_reference.py`) + 미러 |
| 미해결 | 저항 없는 미러 고리(전류가 안 정해짐), 넣는 소자 PMOS·NMOS 섞임 | 후보 탈락 (하네스 대상) |

| 구조 | 입력쌍 | 캐스코드 전 CMRR | 캐스코드 후 (고치기 전) | 원인 |
|---|---|---|---|---|
| TLV271·OPA2376 C3 | NMOS | 3.3 dB | 3.3 dB | NMOS 입력쌍은 VIC 0.4 V 아래에서 꺼짐 (꼬리 노드 0 V). 구조 자체가 범위와 안 맞음 |
| TLV271·OPA2376 D3 | PMOS | 88.5 dB | 61.8 dB | 입력쌍 위 캐스코드 전압을 VCM(2.5 V) 기준으로 정해서 VIC < 1 V 에서 입력쌍 드레인이 2.67 V 로 고정 → 선형 영역 |

고친 것:
1. `auto_size.input_cascode_level`: 입력쌍 위 캐스코드 게이트를 공통모드 범위의 불리한 끝 기준으로 (NMOS 입력 VIC_MAX, PMOS 입력 VIC_MIN).
2. `auto_size.input_cascode_ok` + `cascode.cascode(input_side=None)`: 그 전압으로 쌓을 자리가 없으면 입력쌍 쪽 캐스코드는 빼고 부하 쪽만.
   PMOS 입력 + 범위 0 V 시작이면 게이트가 5.58 V 필요 → 빼게 됨.
3. `rank_v2.py` v4: 입력쌍 종류가 공통모드 범위를 덮는 구조 먼저 (`auto_size.input_pair_covers_range`) → v3.
4. `complement.py`: 입력쌍이 범위를 못 덮고 뒤집으면 덮을 때 NMOS↔PMOS, VDD↔VSS 로 회로 전체를 뒤집음 (연결 모양·이득 노드 수 그대로).
   v4 만 쓰면 TLV271·OPA2376 모델 후보 중 "PMOS 입력 + 이득 노드 2개"가 없어 1-노드 구조가 뽑히므로 뒤집기가 필요.
5. 고리 완성(`EDAI_COMPLETE_LOOPS`)과 캐스코드 전압 맞춤(`EDAI_LEVEL_STACK`)을 기본 켜짐으로. `=0` 이면 끔.

결과 (TLV271 스펙, 실제 바이어스, `data/cascode_test_cmrr.json`, `data/flip_test.json`):

| 회로 | 배율 | AVD (≥97) | CMRR (≥65) | 통과 |
|---|---|---|---|---|
| D3 캐스코드 (고친 뒤) | 20 / 50 | 85.4 / 90.8 | 99.3 / 99.3 | 4/5 |
| C3 뒤집기 | 20 / 50 | 78.0 / 79.7 | 86.4 / 85.6 | 4/5 (전 3/5) |
| C3 뒤집기 + 캐스코드 | 20 / 50 | 85.9 / 87.6 | 99.5 / 95.3 | 4/5 |

CMRR 은 해결. 대신 입력쌍 쪽 캐스코드를 못 쓰게 되어 AVD 가 목표보다 약 10 dB 모자람 (전에는 이득 통과, CMRR 실패).
둘 다 맞추려면 폴디드 캐스코드처럼 입력쌍 드레인을 반대 종류 캐스코드로 접는 구조가 필요 (다음 할 일).

알게 된 것: 우리 측정(`run_sim.py`)은 칩과 상관없이 TLV271 의 공통모드 범위(0 ~ VDD−1.35 V)로 CMRR 을 잰다.
OPA2376 은 비슷하지만(0 ~ V+−1.3 V), OPA320·MCP6441 은 레일 투 레일 입력이라 실제 조건은 더 넓다.

## 4.19 CMRR 을 칩별 조건으로 (2026-11-22 저녁)

`run_sim.load_spec` 이 OP-Amp 스펙을 읽을 때 CMRR 조건 문장에서 공통모드 범위를 읽어 측정 범위로 쓴다 (`parse_cm_range`).
크기 정하기의 입력쌍 검사(`auto_size.vic_min/vic_max`)와 순위 규칙(`rank_v2.load_chip_spec`)도 같은 범위를 쓴다.

| 칩 | 조건 문장 | 측정 범위 (VDD 5 V) | NMOS 입력 | PMOS 입력 |
|---|---|---|---|---|
| TLV271 | VIC = 0 to VDD−1.35V | 0 ~ 3.65 V | 못 덮음 | 덮음 |
| OPA2376 | (V–) < VCM < (V+) – 1.3 V | 0 ~ 3.7 V | 못 덮음 | 덮음 |
| OPA320 | (V–) – 0.1 V < VCM < (V+) + 0.1 V | −0.1 ~ 5.1 V | 못 덮음 | 못 덮음 |
| MCP6441 | VCM = -0.3V to 6.3V, VDD = 6.0V | −0.3 ~ 5.3 V | 못 덮음 | 못 덮음 |

같은 회로(C3 뒤집기, 배율 20)의 CMRR: TLV271 86.4, OPA2376 86.0, OPA320 6.4, MCP6441 7.0 dB.
→ 그 전에 OPA320·MCP6441 에서 CMRR 85~88 dB 로 통과하던 값은 TLV271 조건으로 잰 것이라 맞지 않음.
레일 투 레일 칩은 NMOS·PMOS 입력쌍을 함께 쓰는 구조가 있어야 통과할 수 있다.

## 4.20 AVD 부족과 레일 투 레일 구조 확인 (2026-11-22 저녁)

출력단 배율 시험 (C3 뒤집기 + 캐스코드, TLV271, `data/outscale_test.json`):

| 배율 | 무부하 이득 | AVD (RL 10 kΩ, ≥97) | CMRR | IDD |
|---|---|---|---|---|
| 20 | 98.2 | 85.9 | 99.5 | 678 µA |
| 50 | 98.4 | 87.6 | 95.3 | 807 µA |
| 100 / 200 | 98.4 | 87.6 / 87.7 | 95.3 / 94.3 | 807 µA (그대로) |

배율 50 이상은 크기 정하기의 폭 상한(2 mm)에 걸려 변화 없음. 출력단 키우기로는 약 88 dB 에서 멈춤 → 구조를 바꿔야 함.

학습 데이터의 입력쌍 종류 (`data/train/train.jsonl` 1,672줄): PMOS 887, NMOS 777, 둘 다 8 (실제 구조는 AnalogGenie 320 하나).
OPA320·MCP6441 모델 후보에는 둘 다 쓰는 구조가 없음.
AnalogGenie 320 = 레일 투 레일 폴디드 캐스코드 (NMOS·PMOS 입력쌍을 캐스코드로 접어 합침). 무부하 83 dB, CMRR 98 dB, 출력단이 없어 부하 AVD 2 dB.
→ 이 앞단 + 출력단(2단)이면 레일 투 레일 CMRR 과 높은 이득을 같이 노릴 수 있음 (아직 시험 안 함).

## 4.21 레일 투 레일 폴디드 캐스코드 앞단 + 출력단 시험 (2026-11-22 밤)

학습 데이터의 AnalogGenie 320 앞단(OUT -> N6) + 출력단. 실제 바이어스, `data/r2r_test_tlv271.json`, `data/r2r_test_rest.json`.
A = PMOS 증폭(PM7 G=N6) + NMOS 전류원(NM7 G=VB4). B = 반대 종류는 시뮬레이션이 멈춰 결과 없음.
처음엔 크기 정하기 실패 → 캐스코드 아래 소자를 같은 종류만 보도록, 이득 경로가 캐스코드 소스→드레인을 따라가도록 고침 (e4eac18).
배율 5 는 네 칩 모두 출력이 VCM 에서 벗어나 탈락.

| 칩 | 배율 | 통과 | 못 맞춘 항목 (측정 / 목표) |
|---|---|---|---|
| TLV271 | 20 / 50 | **5/5 / 5/5** | 없음 (AVD 104.9 / 110.9, CMRR 73.2) |
| MCP6441 | 20 / 50 | 6/7 / 6/7 | 위상 여유 15.5 / 29.9° (≥ 52°) |
| OPA320 | 20 / 50 | 2/6 / 3/6 | AVD 105~111 (≥ 114), CMRR 75 (≥ 100), 위상 여유 16~30° (≥ 47°), SR 7.4 (배율 20, ≥ 8) |
| OPA2376 | 20 / 50 | 2/5 / 2/5 | AVD 105~111 (≥ 120), CMRR 73 (≥ 76), IDD 581 / 1202 µA (760 ~ 950) |

공통 약점: 위상 보상 커패시터가 없어 위상 여유가 낮음 → 출력단에 밀러 커패시터(N6–OUT)를 넣는 시험이 다음.
OPA2376·OPA320 는 AVD 목표가 114~120 dB 이상이라 한 단계 더 필요할 수 있음.
이 회로는 모델이 만든 것이 아니라 학습 데이터 앞단에 출력단을 직접 붙인 확인용. 모델이 만들게 하려면 학습 데이터 보강·재학습 필요.
